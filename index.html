How to Create a QR Code

Making a QR code takes less than a minute, and you do not need an account or any design software. Here is the whole process, step by step.

  1. Pick what the code should do Choose a type at the top of the generator. A URL code opens a web page, a Wi-Fi code connects a phone to your network, an email code opens a pre-written message, and phone and SMS codes start a call or text. Picking the right type matters: phones treat each format differently.
  2. Enter your content carefully Type or paste the destination. For links, double-check the spelling — a single wrong character sends people to the wrong page, and a printed code cannot be edited afterwards. For Wi-Fi codes, the network name and password must match your router exactly, including capital letters.
  3. Style it — gently You can change the code and background colours to match your branding, but keep strong contrast: dark modules on a light background scan most reliably. If you plan to print somewhere the code might get scuffed or partly covered, raise the error-correction level to Q or H.
  4. Choose a size and download Pick a download size suited to where the code will live — 512 px is plenty for a document, while posters and signage deserve 1024 px, 2048 px, or the SVG file, which scales to any size without going blurry.
  5. Test before you share Scan the downloaded code with your own phone, and ideally a second phone too, at the distance and lighting where people will actually use it. Only print or publish once it opens the right thing, first try.

A note on links: because a static QR code holds its destination permanently, point it at a page you control whenever you can. If the destination ever needs to change, you can update that page instead of reprinting every code.

Tips for each type

  • URL: shorter links make simpler codes. If your address is long, link to a short landing page rather than a deep, parameter-heavy URL.
  • Wi-Fi: ideal for cafés, rentals and offices. Print it and frame it near where guests sit — and remember the password is visible to anyone who scans, so use your guest network if you have one.
  • Email: pre-fill the subject line with something specific, like an order reference, so replies arrive already organised.
  • Phone & SMS: always include the country code so the number works for visitors from abroad.
  • Text: keep it short. Long text produces a dense code that needs a bigger print size to scan reliably.

QR Code Best Practices

A QR code only earns its place if it scans first time, every time, for everyone. These practical rules — drawn from how scanners actually read codes — will keep yours working.

Print it big enough for the distance

The further away the scanner stands, the larger the code needs to be. As a working rule, a code scanned from arm's length (like a menu or a flyer) should be printed at least about 2 cm (roughly 0.8 in) wide, and codes meant to be read from across a room — posters, window displays, signage — should be far larger, growing in proportion to the viewing distance. When in doubt, go bigger: an oversized code looks bold, while an undersized one simply fails.

Protect the contrast

Scanner cameras look for a clear brightness difference between the dark modules and the light background. Dark code on a light background is the safest combination. Avoid pale colours for the code itself, avoid dark or busy backgrounds, and never invert the code (light modules on dark) — many scanners still struggle with reversed codes. If you use brand colours, test them: two colours can look distinct to the eye yet be nearly identical in brightness to a camera.

Keep the quiet zone clear

Every QR code needs a blank margin — the quiet zone — around all four sides so the scanner can tell where the code starts and ends. Keep text, logos, page edges and other graphics out of this border, and do not crop into it when placing the image in a design. The generator on this site includes the quiet zone by default; leave it switched on for anything printed.

Choose error correction deliberately

Error correction lets a code survive partial damage. Level L keeps the pattern simplest and suits screens and pristine prints. Level M is the balanced default for everyday use. Levels Q and H add more redundancy — worth it for outdoor signs, packaging, stickers and anywhere a code may get dirty, scratched or partly covered. The trade-off is density: higher correction packs more modules into the same space, so pair it with a slightly larger print size.

Do not distort or decorate the pattern

Never stretch a code wider or taller, rotate it at odd angles in print, or place images over its modules. Keep it square, keep it flat, and keep every module intact. If you want a logo near the code, put it beside the code — not inside it.

Mind the surface and placement

Glossy lamination, curved bottles, folds, creases and harsh reflections all make scanning harder. Favour matte finishes and flat surfaces, place codes at a comfortable scanning height, and think about lighting: a code in deep shadow or direct glare will frustrate people. Also give scanners a reason and a hint — a short line such as "Scan to see the menu" beside the code tells people what they will get.

Test like a stranger would

Before any print run, scan the final artwork — not the screen preview — with more than one phone, including an older or budget model if you can. Test at the real distance, in the real lighting, on the real material. Check that the code opens exactly the right page or action, and re-test after any change to colours, size or content. Thirty seconds of testing is cheaper than reprinting.

Keep the destination healthy

A static code is permanent, so the page it points to has to live as long as the print does. Use an address you control, keep that page online, and make sure it loads quickly and reads well on a phone — because a phone is what every visitor will be holding.

The short version: big enough, dark on light, quiet zone intact, error correction matched to the environment, tested on real phones. Follow those five and your codes will scan.

Frequently Asked Questions

Straight answers about how QR codes work, what this tool does with your data (nothing), and how to get codes that scan reliably.

Is my data uploaded or stored?

You can even load the page and then go offline — the generator will keep working.
What can I put in a QR code?
This tool supports six types: website links, plain text, Wi-Fi network details (so guests can connect without typing a password), email addresses with a pre-filled subject and message, phone numbers that can be tapped to call, and SMS messages with the text already written.
Which error-correction level should I choose?
Level M is a good everyday default. Choose Q or H if the code will be printed somewhere it may get scuffed, dirty or partly covered, because higher levels let the code survive more damage. Choose L when you want the simplest, least dense pattern for clean, controlled conditions such as on-screen display.
Why won't my QR code scan?
The usual causes are low contrast between the code and its background, printing it too small for the scanning distance, a missing or cropped quiet zone (the blank border), glare or damage on the print, or a very dense code (from long content) printed too small. Keep dark modules on a light background, include the quiet zone, size generously, and always test with a real phone before printing in quantity.
Can I change where a QR code points after printing it?
Not with a static code — the destination is baked into the pattern, so changing it means generating and printing a new code. If you expect the destination to change, point the code at a page you control; then you can update that page whenever you like and every printed code follows.
Should I download PNG or SVG?
PNG is a ready-to-use image that suits documents, slides, social posts and most everyday printing. SVG is a vector file that stays perfectly sharp at any size, which makes it the better choice for professional print work, signage and large formats. Both contain exactly the same code.
How big should I print my QR code?
It depends on the scanning distance. For something held in the hand, like a menu or business card, print at least about 2 cm (0.8 in) wide. For posters and signs read from further away, scale up in proportion to the distance — and test the printed result before committing to a full run. Our best practices guide covers sizing, contrast and placement in detail.
Do people need a special app to scan my code?
In most cases, no. The camera apps built into modern phones recognise QR codes automatically — the user points the camera at the code and taps the prompt that appears. Older devices may need a free scanner app, but they are the exception rather than the rule.

QR Code Sizes and Printing Guidelines

Most QR code failures are not technology failures — they are size failures. A code that is too small for the distance it is scanned from will defeat even the best phone camera. This guide explains how to choose a print size that works, and how to print it cleanly.

The one rule that matters: size follows distance

A phone camera needs each module — each little square in the pattern — to occupy enough pixels in the image to be told apart from its neighbours. The further the phone is from the code, the smaller each module appears, so the code itself must grow. A widely used working ratio is 10:1: the scanning distance should be no more than about ten times the width of the code. A code scanned from 30 cm away therefore wants to be at least 3 cm wide, and a poster read from two metres away needs a code of roughly 20 cm or more.

In practice, most everyday codes are scanned at arm's length or closer. For those, the floor is about 2 cm (0.8 in) wide — the minimum you will see recommended in our best practices guide as well. Business cards can sometimes go slightly smaller with a very simple code, but 2 cm is the safe line for anything a stranger must scan first try.

Density changes the answer

Not all codes of the same width are equally easy to scan. A code holding a short link has relatively few, large modules; a code holding a long URL, a full vCard or a paragraph of text packs in far more, much smaller modules. The denser the code, the larger it needs to print. This is why shortening your content — using a short link instead of a long one, trimming tracking parameters — genuinely improves reliability, a point we return to in common QR code mistakes. If your code looks busy and fine-grained on screen, give it extra size in print.

Error correction plays into this too. Higher levels add extra modules, making the pattern denser. If you choose level Q or H for a code that will live outdoors, as explained in our guide to error correction levels, budget a little more print size to compensate.

Resolution: start from a big enough file

Print size is only half the story; the file you print from must carry enough detail. A small image stretched across a large area blurs module edges, and blurred edges are what scanners trip over. For print, download at a generous size — the generator on this site offers PNG exports up to 2048 × 2048 px — or choose the SVG, which is a vector file that stays perfectly sharp at any dimension. Our comparison of QR code file formats explains when each is the right pick. As a rough check, your image should have at least 300 pixels per inch of printed size for crisp results on paper.

Paper, finish and placement

Matte paper is kinder to scanners than glossy stock, because gloss reflects light into the camera and can white out part of the pattern. If you must laminate, choose a matte laminate. Print on flat surfaces where possible: codes wrapped around bottles, folded across creases or stuck on curved packaging distort the grid and slow scanning down. Keep the code away from page edges and folds, and preserve the blank quiet zone around it — that margin is part of the code, not decoration.

Placement matters as much as the print itself. Put codes where a person can comfortably hold a phone in front of them: roughly chest to eye height for wall signs, flat on tables for menus, never so low or high that scanning becomes a stretch. Think about lighting too — a code in a dim corridor or under a spotlight that glares will underperform no matter how well it was printed.

A quick sizing reference

  • Business cards and labels: 2–2.5 cm, simple code, scanned in the hand.
  • Flyers, menus and table tents: 2.5–4 cm, scanned at arm's length.
  • Posters and window displays: 8–15 cm, scanned from one to two metres.
  • Signs, banners and vehicle graphics: 20 cm and up, scaled to the real viewing distance.

Test the actual print

Finally, always proof before a print run. Print one copy on the real printer, on the real paper, stick it where it will live, and scan it with more than one phone — including the oldest one you can find — at the real distance and lighting. If it scans instantly for everyone, your size is right. If anyone has to shuffle closer or hunt for the angle, go bigger. Thirty seconds of testing is far cheaper than a reprint. QR Codes for Wi-Fi Sharing: Connect Guests Without Typing Passwords

Few small frustrations are as universal as reading a long Wi-Fi password aloud, character by character, while a guest squints at their phone. A Wi-Fi QR code ends that ritual: one scan and the phone joins the network. Here is how it works and how to use it well.

How a Wi-Fi QR code works

A Wi-Fi QR code is simply a text code in a standard format that phones recognise. It contains three things: the network name (the SSID), the password, and the security type — usually WPA, which covers WPA2 and WPA3 networks. When a phone's camera sees this format, it does not just show the text; it offers a "join network" prompt, and one tap connects the device. No typing, no mistaking a zero for the letter O, no asking the host to repeat the password.

You can make one in seconds with the Wi-Fi tab of our QR code generator: enter the network name exactly as it appears in your router settings, add the password, pick the security type, and download. The step-by-step guide covers the general process if you are new to it.

Where Wi-Fi codes earn their keep

At home, a framed code near the front door or in the guest room saves the password dance every time friends visit. In holiday rentals, it is close to essential: guests arrive tired, and instant internet is one of the easiest wins for a good review. In cafés, salons and waiting rooms, a code on the counter or table turns "what's the Wi-Fi?" from a repeated staff interruption into a self-service moment. In offices, a code in the meeting room lets visiting clients and contractors get online without involving IT.

The security conversation, honestly

A Wi-Fi QR code is a printed password. Anyone who scans it — or photographs it — can read the credentials it contains, and scanner apps typically show the password in plain text after connecting. That is not a flaw in the code; it is the nature of sharing a password at all. But it should shape where you put the code and which network it opens.

The cleanest setup is a guest network. Most modern routers can broadcast a separate network for visitors, isolated from your main one where your computers, storage and smart devices live. Give the guest network its own password, print the code for that, and change the guest password occasionally if the code lives somewhere public. For a business, this also keeps customer traffic separate from the network your tills and office machines use. If your router has no guest option, place the code where only genuine guests will see it — inside a rental's welcome folder rather than in its listing photos, for instance.

Making the code itself

Accuracy matters more here than anywhere: the network name and password must match the router exactly, including capital letters and spaces, or the phone will fail to connect and the guest will not know why. Copy the details from your router's admin page or the sticker on the router rather than from memory. If your network is hidden — it does not broadcast its name — tick the hidden-network option in the generator so phones know to look for it.

Keep the design simple. A plain, high-contrast code on a small card or sign scans best, and this is a case where the best practices about quiet zones and contrast really pay off. Add a short line of text — "Scan to join our Wi-Fi" — so people know what the code does before they scan it, which is also good safety practice: a labelled code is a trustworthy code.

When the password changes

Wi-Fi codes are static: the password is baked into the pattern, so if you change the password you must print a new code. That is a small job — regenerate, reprint, replace — but do remember to actually do it, and to collect the old prints. Cafés and rentals that rotate passwords monthly often keep the code in a frame or a stand so swapping it takes seconds.

Done well, a Wi-Fi QR code is one of the highest-value uses of the technology: a permanent end to spelling passwords aloud. Create yours with the generator, test it with your own phone from a signed-out state, and put it where your guests will find it.

QR Codes for Restaurant Menus: A Practical Guide

Table QR codes went from novelty to fixture in a few years, and they are staying — not because restaurants love technology, but because guests like instant menus and owners like never reprinting them. This guide covers doing it properly.

What the code should point to

The code on the table has one job: open the menu, fast, on a phone. That means the destination matters more than the code itself. Link to a mobile-friendly menu page on your own website — a page that loads quickly, reads well in bright light, and needs no pinch-zooming. A PDF can work if it is small and well formatted, but large PDF menus are the most common complaint about QR dining: slow to load, awkward to scroll, and miserable on older phones.

Point the code at a page you control rather than a file buried in a third-party service. Menus change — prices, seasons, sold-out dishes — and because a printed QR code is permanent, the flexibility has to live in the page behind it. This is the same reasoning behind the static vs dynamic choice: a static code pointing at your own menu page gives you most of the editability with none of the subscription. Create the code with a free QR code generator, link it to your menu page, and the printed table tents never need to change when the menu does.

Size and placement on the table

Table codes are scanned from 20–40 cm, so 2.5–4 cm wide is the comfortable range — bigger than the bare minimum, because table lighting is often dim and romantic rather than scanner-friendly. Our sizes and printing guide has the full distance chart. Print on matte material: glossy table tents under downlights glare badly. Tent cards, acrylic stands and stickers all work; whatever you choose, the code should sit flat, upright and reachable from both sides of the table where possible.

Every code needs a caption. "Scan for the menu" plus, ideally, a hint of what else is there — "Scan to view the menu and today's specials" — measurably increases scans, because people scan when they know what they will get. This is basic best practice, and it costs one line of text.

Design that survives a dining room

Branding is welcome — your colours, your typeface on the card around the code — but the code itself should stay dark on light with its quiet zone intact, as our design tips explain. Dining rooms are hard on printed materials: codes get splashed, wiped, faded by window sun and handled hundreds of times. Choose error correction level Q or H so a scuffed corner does not kill the code, and inspect table materials monthly; a faded tent card is a broken menu.

Do not make the code the only door

Some guests will not or cannot scan: their phone is dead, their camera is broken, they have low vision, or they simply prefer paper. A restaurant that keeps a few printed menus and staff happy to bring one loses nothing and excludes nobody. Our article on QR code accessibility covers this properly. The QR menu should be the fast lane, not a locked gate.

It is also worth training staff on the two questions they will get: "how do I scan this?" (open the camera, point, tap the banner) and "can I just have a menu?" (yes). A ten-second answer keeps the experience warm.

Getting more from the same code

Once guests trust your table code, the menu page can carry more than the menu: a link to book again, your loyalty scheme, the day's specials, or a feedback form. You can also learn from the traffic — the guide to tracking scans shows how to see which tables and times generate menu views, using nothing more exotic than your website analytics. Keep the menu itself one tap away, though; extras should never bury the thing the guest scanned for.

QR Code Error Correction Levels Explained (L, M, Q and H)

Every QR code carries backup copies of its own data. That is why a code with a coffee stain or a torn corner often still scans. The four error correction levels — L, M, Q and H — decide how much backup you get. Here is what each one really does.

How error correction works, in plain terms

When a QR code is generated, the data is not written into the pattern just once. Extra "check" data, calculated mathematically from the original content using a method called Reed–Solomon error correction, is woven into the pattern alongside it. If part of the code is later damaged, obscured or misread, the scanner can reconstruct the missing pieces from the check data — the same principle that let scratched CDs keep playing.

The catch is that the backup data takes up room. The more correction you add, the more of the pattern is given over to redundancy, and the denser the code becomes for the same content. Error correction is therefore a trade: more damage tolerance, but a busier pattern that needs a decent print size to stay readable. That density trade-off is why level choice belongs in the same conversation as print size.

The four levels, by the numbers

  • Level L (Low) — roughly 7% of the code can be damaged or hidden and the code still reads. The simplest, least dense pattern of the four.
  • Level M (Medium) — roughly 15% damage tolerance. The balanced default most generators start from.
  • Level Q (Quartile) — roughly 25% damage tolerance, for codes that will live a harder life.
  • Level H (High) — roughly 30% damage tolerance. The maximum protection, and the densest pattern.

Those percentages refer to the share of the code's data area that can be unreadable — a splash, a scratch, a sticker peeling — not a guarantee about any particular tear. Damage concentrated in the wrong place (the finder patterns in the corners, for instance) can defeat even level H, which is why physical placement still matters; see best practices.

Which level should you choose?

On screens and in clean conditions, L or M. A code displayed in an app, a slide deck or an email lives a sheltered life. Level M is the sensible default: meaningful protection without unnecessary density. If the code is very content-heavy — a long link or a full vCard — and will only ever be shown on screen, L keeps the pattern as simple as possible.

For print that gets handled, Q. Menus, packaging, labels, leaflets and anything passed hand to hand picks up wear. Q survives the scuffs of everyday life without making the code dramatically denser.

For harsh environments and logos, H. Outdoor signs, stickers, vehicle graphics and codes on products that get dirty or wet deserve H. It is also the level to use if you place a small logo in the centre of a code — the logo deliberately covers part of the pattern, and H's 30% tolerance is what makes that survivable, as discussed in our design tips. Even then, keep the logo modest and test thoroughly.

Common misunderstandings

Higher is not automatically better. Choosing H "just in case" for a dense code printed small can actually make scanning worse, because the extra density shrinks each module. Match the level to the environment, then size the print for the level you chose. Nor does error correction fix other problems: it cannot rescue low contrast, a cropped quiet zone or a wrong URL. Those are separate failure modes, covered in common QR code mistakes.

Finally, the level is fixed when the code is created — you cannot upgrade a printed code afterwards. If you are unsure between two levels for a print job, pick the higher one and print slightly larger. Static vs Dynamic QR Codes: Which Do You Need?

"Static" and "dynamic" are the two families every QR code belongs to, and choosing between them shapes what your code can do forever after. The difference is simpler than the marketing around it suggests.

What a static code is

A static QR code encodes its content directly into the pattern of squares. A static link code literally contains the URL, spelled out in modules; a static Wi-Fi code contains the network name and password themselves. Because the destination is the pattern, a static code can never be edited and never expires. It does not pass through anyone's server, so there is nothing to switch off, no account to lapse, and no company whose closure could break your printed posters. Every code made by the generator on this site is static, generated locally in your browser.

The limitation is the mirror image of the strength: if the destination changes, the printed code cannot follow. Print a static code for a page that later gets deleted, and the code faithfully leads people to a dead end.

What a dynamic code is

A dynamic QR code encodes a short redirect address owned by a QR service. Scanning it takes the phone to the service's server first, which forwards it to the real destination. Because the service controls that forwarding, the owner can change the destination after printing, see scan statistics, and sometimes schedule or target redirects. The pattern itself stays the same while the target moves.

Those powers come with strings. Dynamic codes almost always require a paid subscription, and the code works only while the service keeps redirecting — stop paying, or the provider shuts down, and every printed code dies at once. Your scan data also lives on someone else's system, under their privacy policy, not yours.

Side by side

  • Editing afterwards: static — no; dynamic — yes, that is its main selling point.
  • Scan tracking: static — not built in (but see below); dynamic — usually included.
  • Cost: static — free to create, forever; dynamic — typically a monthly subscription.
  • Permanence: static — works as long as it is readable; dynamic — works while the subscription and provider last.
  • Density: static — as dense as its content; dynamic — usually a short redirect, so a simple pattern.
  • Privacy: static — no middleman sees the scans; dynamic — the provider logs every scan.

The middle path most people miss

Many people buy dynamic codes for one reason: fear that the destination will change. But you can get most of that flexibility with a static code by pointing it at a page you control. Print a static code for your own menu page, landing page or link page, and you can update that page's contents — new menu, new offer, new file — whenever you like, while the printed code stays valid forever. Restaurants use this pattern constantly, as our restaurant menu guide explains. Pair the page with ordinary website analytics and you recover much of the tracking too; our guide to tracking QR code scans shows how.

Dynamic codes still have genuine uses: large campaigns where different regions or dates need different destinations, print runs so expensive that reprinting is unthinkable, or teams who need built-in scan dashboards and can accept the ongoing cost and dependency. If you go that route, choose a provider you expect to outlive your print, and export your data regularly.

Our recommendation

For the large majority of uses — menus, Wi-Fi, business cards, posters, packaging, events — a static code pointing at something you control is simpler, free, private and permanent. Reach for dynamic only when post-print editing or built-in analytics is a hard requirement you cannot meet any other way. QR Code Safety: How to Spot and Avoid Quishing Scams

A QR code is a link you cannot read. That single fact is what makes codes so convenient — and what scammers exploit. "Quishing" (QR phishing) is now a standard trick, but a few habits make it easy to defeat.

How QR scams actually work

The classic setup is a sticker over a genuine code. A criminal prints their own code — pointing to a convincing fake payment or login page — and sticks it over the real one on a parking meter, a restaurant table, a charging point or a poster. You scan what looks like the venue's code, land on a page that looks right, and hand your card details or password to a stranger. Variants arrive by email and post too: a letter or message claiming to be from a bank, a delivery firm or a tax office, inviting you to scan a code to "verify" something — often precisely because QR codes slip past email security filters that would catch a suspicious link.

The destination page does the damage, not the code itself. The code is just the delivery mechanism, which means your defence is the same as for any suspicious link: look before you leap.

Warning signs to check before you trust a code

  • The code looks tampered with. A sticker on top of another code, a loose or misaligned print, or a code that looks newer than everything around it deserves suspicion. On parking meters and payment points, run a fingernail over it — a genuine code is usually printed on the surface, not stuck on it.
  • The preview address looks wrong. Most phones show the destination before opening it. Read it. Misspellings, odd domains, extra words and URL shorteners hiding the real address are all red flags — a council parking page should not resolve to a random string of characters on an unrelated domain.
  • It asks for too much. A menu code should open a menu. A payment code should open a payment page for a plausible amount. If a "menu" asks for your bank login, or a "delivery" code asks you to install an app or pay a redelivery fee by card, stop.
  • The context pressures you. Urgency — fines doubling, accounts closing, parcels returned — is the scammer's favourite tool, on paper and screen alike. A real organisation will also reach you through its normal channels.

Safer scanning habits

Use your phone's built-in camera rather than a third-party scanner app; the built-in one previews destinations and is maintained by the platform. Preview before opening whenever your phone offers the choice, and read the domain the way you would read a link in an email. Never enter banking credentials or card details on a page reached from a public QR code if you can use the organisation's official app or type its address yourself instead — for payments, our guide to QR payments covers the safer patterns. And keep your phone updated, since modern browsers block many known malicious pages automatically.

If you publish codes, protect your audience

Safety runs both ways. If your business prints codes, make them hard to fake and easy to verify: print codes directly on materials rather than as loose stickers where you can, include your branding and a caption saying exactly where the code leads ("Scan to pay at the till — we never ask for bank logins"), and inspect your public codes regularly for overlays — cafés, car parks and venues should treat this like checking a lock. Tell customers what the genuine destination looks like. A labelled code following best practices is both more usable and more trustworthy.

None of this is a reason to fear QR codes — billions of scans a day end exactly where they should. It is a reason to treat an unknown code like an unknown link: glance at where it is going before you follow it. And when you create your own codes with a tool like our generator, remember they are static and point exactly where you set them — no redirects, no surprises — which is the safest kind of code to publish.

A business card has seconds to do its work before it joins a stack. A QR code turns those seconds into a saved contact, a booked call or a viewed portfolio. Here is how to add one without ruining the card.

Decide what the scan should do

One card, one code, one job. The strongest choices are: save your contact details (a vCard code — see our vCard guide), open your booking page so a new contact can schedule a call on the spot, show your portfolio or catalogue, or open your link page with your profiles and latest work. Saving the contact is the most common and usually the most valuable, because a card that becomes a phone contact never gets thrown away. Whatever you choose, the destination must be fast and phone-friendly — the person scanning is holding your card in one hand and their phone in the other.

Size: small card, strict limits

A standard business card is about 85 × 55 mm, which leaves little room for generosity. The working minimum for a printed code is around 2 cm wide, and on a card you should treat that as a floor, not a target — aim for 2–2.5 cm plus its quiet zone. Our sizes and printing guide explains why distance and density set this limit. Density is your lever: a vCard packed with every detail you own makes a dense code that struggles at small sizes, so trim the content to what a new contact actually needs. A link code to a contact page is simpler still, and has the bonus that the page can be updated later — the pattern described in static vs dynamic QR codes.

Placement and layout

The back of the card is prime real estate: one code, centred, with room to breathe and a caption beneath it. Putting the code on the back also keeps the front clean for your name and role, which remain the card's headline. If the code must share the front, give it a corner and keep everything else — logos, text, edges — out of its quiet zone. Never run the code to the very edge of the card; trimming in print is not perfectly precise, and a clipped quiet zone is a common cause of the failures listed in common QR code mistakes.

Add a caption, always. "Scan to save my contact" outperforms a naked code because it tells the holder what they gain. It also sets expectations correctly, which matters for trust — an unexplained code on a card is a code many people will not scan, as our safety guide explains from the scanner's side.

Colour and finish

Brand colours are welcome on the card and cautious around the code. Matte or soft-touch finishes scan better than high gloss, which reflects light into the camera. Test with the real card

vCard QR Codes: Share Your Contact Details with One Scan

Typing someone's details from a business card into a phone is where contact information goes to die. A vCard QR code skips the typing: scan it, tap save, and the contact is in the phone — correctly spelled, complete, and searchable forever.

What a vCard is

vCard is the long-standing standard format for electronic contact cards — the .vcf file your phone already uses when it shares or saves a contact. A vCard QR code simply packs that same structured text into a QR pattern. Inside, fields are labelled: name, organisation, job title, phone numbers, email, website, address, even a note. Because the data is structured rather than a free-text blob, the phone knows exactly what to do with it and presents a ready-made "add contact" screen when the code is scanned. No app, no account, no copying and pasting.

What to include — and what to leave out

A good vCard contains what a new contact needs to reach you and remember you: your full name, job title and organisation, your main phone number (with country code, so it works internationally), your email address, and your website. A short note field — "Met at the Spring Trade Fair" style context does not belong in your own card, but a line about what you do can help the contact remember why they saved you.

Restraint matters for a technical reason: every field adds data, and more data means a denser code. A dense vCard printed small is a scanning struggle, which is why the business card guide recommends trimming to essentials. Skip the fax number nobody uses, the second and third email addresses, and the full postal address unless your contacts genuinely need it. If you want to share everything, put a short link code on the card instead and let a contact page carry the weight.

vCard code or link code?

The vCard's great strength is that it works offline and forever: the details are in the pattern, so the contact saves even with no signal, and the code never depends on a website staying up. Its weakness is the mirror image — when your number or role changes, every printed vCard is wrong, permanently, as with any static code (see static vs dynamic). A link code pointing at your contact page can be updated centrally but needs connectivity and a living page. Many professionals compromise: a vCard code for the details that rarely change, on materials with a short life, and a link code on anything meant to last for years.

Making and using one well

Build the vCard text carefully — one typo in a phone number saves a wrong contact very efficiently — and generate the code at error correction level M or Q so it survives life on paper. Size it generously for where it will appear: at least 2 cm on a card, larger on a name badge, desk sign or conference banner, following the distance rules in our printing guide. Label it plainly — "Scan to save my contact" — so people know the payoff before they scan.

Then test it the way a stranger would: scan with an iPhone and an Android phone, confirm the contact saves with every field in the right place, and check the number dials correctly. Beyond cards, vCard codes shine on email signatures (as an image), presentation closing slides, shop counters, vehicle signage and event badges — anywhere meeting you should end with being saved. How to Track QR Code Scans and Measure Results

Print is famously hard to measure, and QR codes are print's answer: every scan is a visit you can count. But a static code has no built-in counter — so how do you actually track scans? Honestly, and without expensive tools.

First, understand what can be counted

A QR code itself records nothing. What you can measure is what happens at the destination: when a scan opens your web page, your website analytics see a visit like any other. So tracking QR codes really means tracking the visits your codes generate, and separating them from visits that arrived by other routes. Everything below is a way of labelling those visits so they stand out. (Dynamic code services count scans at their redirect server instead — one of their genuine features, weighed in static vs dynamic QR codes — but the methods here give static-code users most of the same insight for free.)

Method 1: a dedicated landing page

The simplest reliable method: point the code at a page that exists only for that code — yoursite.com/menu, yoursite.com/flyer, yoursite.com/spring-offer. Every visit to that address came from the code (or from someone typing the short address, which is also a response to your print). Your analytics show the visit count, times, devices and what people did next. This is why the restaurant menu pattern — one stable menu page behind the table code — doubles as a measurement tool.

Method 2: campaign parameters (UTM tags)

If several codes point to the same page — posters in three locations, a code in a magazine and one on packaging — give each printed version its own tagged link. Adding parameters such as ?utm_source=print&utm_medium=qrcode&utm_campaign=poster-station to the URL makes analytics report each version separately, so you can see which placement earns its space. Two cautions: longer URLs make denser codes, so keep tags short and meaningful; and generate a separate code for each version — the tag lives in the code, so each placement needs its own print. Our creation guide covers checking long links before you commit them to a code.

Method 3: your own redirect page

A step up in effort: point the code at a tiny page on your own site that instantly forwards visitors to the real destination. Your server logs count every hit on that address, giving you a scan count even when the final destination is a file, a form or someone else's platform. This is effectively building your own minimal dynamic code — with the permanence of owning it. Keep the redirect instant and reliable; a slow hop loses visitors and skews numbers.

What to look at once you have numbers

  • Scans over time: spikes after distribution, decay as posters age — tells you when to refresh placements.
  • Scans by placement: which locations, tables or publications actually perform, so budget follows evidence.
  • What happened next: a scan that ends in a booking, purchase or sign-up is worth more than raw scan counts. Judge codes by outcomes, not scans alone.
  • Device and time patterns: mostly phones, obviously — but lunchtime vs evening, weekday vs weekend patterns help time your offers.

Honesty about the limits

These methods count visits, not scans: someone who scans and closes the tab instantly, or whose connection fails, may never register. Treat the numbers as a dependable floor and a fair comparison between placements, not an exact census. Also respect privacy: aggregate analytics are fine, but do not try to identify individual scanners, and say what you collect in your privacy notice. Measured sensibly, though, even simple counts transform print decisions from guesses into evidence — and every code you need for it can be made free with the generator.

QR Code Design Tips: Colours, Logos and Branding That Still Scan

A QR code does not have to be a black-and-white eyesore in the corner of your design. It can carry your colours and sit comfortably in your branding — as long as you respect the few rules scanners actually care about. Here is where the freedom is, and where it ends.

The one rule underneath all the others

Scanners read contrast in brightness, not colour as humans see it. The modules must be clearly darker than the background behind them. Any dark colour on any light background can work — deep navy, forest green, burgundy, dark plum — and the pairing can absolutely be your brand palette. What fails is low brightness difference: pastel pink on cream, mid-grey on light grey, gold on white. Two colours can look obviously different to you yet be nearly the same brightness to a camera. When you pick colours in our generator, it warns you when the pair is too close in brightness — treat that warning as a hard stop, and test the final artwork regardless.

Never invert the code — light modules on a dark background. Some modern phones cope; many scanners, especially older ones and those built into other apps, still fail on reversed codes. If your design is dark, set the code in a light panel. The panel becomes part of the design; the code inside stays conventional.

Colour the code, keep the structure

Safe customisations: the module colour, the background colour (including transparent-looking light tints, provided the printed surface behind them stays light), and gentle styling around the code — frames, captions, brand graphics nearby. Risky customisations: gradients across the code (brightness varies module to module), patterns or photos behind the modules, and rounding or reshaping the modules themselves. Some generators offer dots and rounded corners; heavily restyled modules reduce the margin for error, especially at small sizes. If you restyle, compensate with a larger print size and stricter testing — the size rules are in our printing guide.

Logos in the centre: possible, carefully

Placing a small logo over the centre of a code works because error correction rebuilds the covered data. The conditions are strict: use error correction level H, keep the logo small — a modest centre mark, well under a third of the code's area — and keep it away from the three corner finder patterns, which scanners need intact to orient themselves. Then test relentlessly, on several phones, at the real size. If any phone hesitates, shrink the logo or drop it. A logo beside the code, in a branded frame, achieves most of the recognition with none of the risk, and is what we recommend for anything printed in quantity.

Frames, captions and calls to action

The design around the code is where branding should live. A frame in your brand shape, your typeface on the caption, an icon showing what the scan delivers — all of this raises scan rates because people scan when they understand the offer. Write the caption as a small promise: "Scan to see the menu", "Scan to save my contact", "Scan for the virtual tour". Keep clear space between the frame's inner edge and the code itself: the quiet zone is part of the code, and crowding it is one of the common mistakes that silently break scans.

A safe design workflow

  1. Generate the code in black on white first, and confirm it scans.
  2. Apply your dark brand colour to the modules; re-test.
  3. Add background tint, frame and caption; re-test.
  4. If adding a centre logo, switch to level H and keep it small; re-test on multiple phones.
  5. Test the final printed piece, at final size, in real light — not the screen file.

Follow that order and design stops being a gamble: each change is verified before the next is added. QR Codes vs Barcodes: What Is the Difference?

The striped barcode and the square QR code look like relatives, and they are — both encode data in a pattern machines can read. But they were built for different jobs, and the differences explain why each still thrives.

One dimension versus two

A traditional barcode (such as UPC or EAN, the kind on groceries) stores data in one dimension: the varying widths of vertical bars, read left to right. That limits it to a small payload — typically just a product number, around 12 digits, which a shop's system looks up in a database to find the price and description. The barcode itself holds almost nothing; the database holds everything.

A QR code stores data in two dimensions, across both the horizontal and vertical axes of its grid of squares. That change multiplies capacity enormously: a QR code can hold thousands of characters — a full web address, Wi-Fi credentials, a structured contact card, a paragraph of text — with no database lookup needed. The information travels with the pattern itself. This is why a code from our generator works with no server involved: everything is in the squares.

Reading them

Barcodes are traditionally read by laser or LED scanners that sweep the bars — fast and superb at a checkout, where a beep per item keeps queues moving. QR codes are read by cameras: the phone photographs the whole grid at once, finds the three corner patterns to orient itself, and decodes the data in any rotation. That is why any smartphone scans QR codes natively, while phone barcode scanning, though possible, is slower and fussier. QR codes also forgive damage: built-in error correction lets them survive scratches and stains that would kill a barcode, whose single row of data has no backup.

Where each one wins

  • Retail checkout and inventory: the barcode still rules. It is tiny, prints on anything, scans in a blink with cheap hardware, and plugs into decades of product databases.
  • Connecting phones to things: the QR code wins outright — links, menus, payments, Wi-Fi, contacts — because it carries the destination itself and every customer already owns the scanner.
  • Tickets, boarding passes and coupons: both appear (airlines use a specialised 2D cousin called PDF417), but QR codes dominate consumer-facing uses for their capacity and phone-friendliness.
  • Manufacturing and parts: 2D codes (QR and its industrial sibling DataMatrix) mark components because they hold serial data in a tiny, damage-tolerant square.

Do you ever need both?

Packaging often carries both, for good reason: the barcode serves the shop's checkout and stock systems, while the QR code serves the customer — linking to instructions, recipes, registration or support. They are not competitors on the same label; they talk to different audiences. If your need is "a person with a phone should reach my page or details", that is a QR code, and our step-by-step guide will get you one in a minute. If your need is "a till should price this item", that is a barcode issued through the retail numbering system — a different process entirely, and not something a QR generator replaces.

A note on cost and equipment

One more practical difference: getting started. A business that wants product barcodes joins a numbering organisation, pays for its number range, and buys scanners suited to its tills — a real, if modest, investment in infrastructure. A business that wants QR codes needs a generator, a printer and the phones its customers already carry; the codes on this site are free, and creating one takes under a minute. That asymmetry is a large part of why QR codes spread to menus, markets and classrooms while barcodes stayed where the tills are: each technology is cheapest exactly where it is strongest.

In short: barcodes are identifiers that point at a database; QR codes are containers that carry the information with them. Knowing which of those your situation needs is the whole decision — and the FAQ answers the follow-up questions people usually ask next.

QR Codes for Payments: How Pay-by-QR Works

From market stalls to restaurant bills, "scan to pay" has become one of the most visible uses of QR codes. It works in two distinct ways, and understanding them helps both customers and businesses use it safely.

The two ways a payment code works

In the merchant-presented model, the shop displays a code — on a counter card, a receipt or the bill — and the customer scans it with their banking or wallet app, enters or confirms the amount, and pays. The code identifies the merchant's account; the customer's app does the rest. This is the model behind the counter signs in cafés and stalls worldwide, because it needs no card terminal at all: a printed code and a phone are the entire infrastructure.

In the customer-presented model, the roles flip: the customer's app displays a personal code (often alongside a barcode), and the merchant scans it with their till or terminal to draw the payment from the customer's account. Transit systems and large chains favour this model because it is fast at the till and works with their existing scanners.

Why businesses adopt it

The appeal is practical. Accepting QR payments can cost far less than card payments in fees, requires no rented terminal, settles directly to a bank account in many systems, and suits exactly the places cards struggle — markets, food trucks, tradespeople, charities collecting donations, and invoices sent by email or post, where a code on the invoice lets the customer pay in seconds instead of typing account numbers. For sole traders, a printed code in a stand can be the entire card machine.

What the code contains — and an important distinction

A payment code is not something a general-purpose generator should improvise. It encodes a payment address in the format your bank or payment provider specifies, tied to their app ecosystem — the details differ between providers and countries, and a mistyped digit sends money nowhere useful. So: use the code your payment provider issues for receiving money, exactly as issued. Where a general generator like our QR code generator does help is the surrounding jobs — codes linking to your payment page, your invoice portal, or your booking-and-pay flow — where the code carries an ordinary web address and the payment itself happens on the page.

Safety, for both sides of the counter

Payment codes attract the exact scam described in our safety guide: a criminal sticks their own code over a merchant's, and customers pay the wrong account. Businesses should print codes on materials that are hard to overlay, place them where staff can see them, and check them daily — a fingernail test for stickers takes seconds. Customers should confirm the merchant name shown in their app before confirming payment: legitimate apps display who is being paid, and a mismatch is the moment to stop. Never pay a code that arrived in an unexpected message asking for urgent fees; go to the organisation's official app or site instead.

Getting started as a business

Choose the payment service your customers already use, obtain its official merchant code, print it generously sized — counter codes are scanned at arm's length, so follow the size guidance — and caption it clearly: "Scan to pay with [app name]". Test a small real payment end to end before the first busy day, and keep a second payment option available for customers whose phones or apps cannot scan, in line with the accessibility principle that a code should be a shortcut, never the only door. Done that way, pay-by-QR is fast, cheap and genuinely convenient — which is why it is not going away.

PNG, SVG or EPS: Choosing the Best QR Code File Format

Your QR code is made — now which file do you download? The choice between PNG, SVG and EPS is really a choice between pixels and vectors, and picking correctly is the difference between a crisp print and a fuzzy one.

The core distinction: raster vs vector

A raster image (PNG, and also JPG) stores the picture as a grid of pixels at a fixed size. Enlarge it beyond that size and the software invents the in-between pixels, softening edges — and a QR code is nothing but edges, so softness directly harms scanning. A vector file (SVG, EPS, PDF) stores the drawing as shapes and instructions instead, so it can be rendered at any size with perfectly sharp edges forever. A QR code, being pure geometry, is the ideal vector citizen.

PNG: the everyday workhorse

PNG is the right choice for most on-screen and office uses: documents, slides, emails, social posts, websites, and small-to-medium printing. It supports crisp black-and-white contrast with no compression artefacts — which is why you should always prefer PNG over JPG for QR codes; JPG's lossy compression smudges module edges with grey fuzz that scanners dislike. The one discipline PNG demands is size: download it bigger than you need. Our generator offers up to 2048 × 2048 px, which covers print up to a large poster at good resolution; the printing guide explains the pixels-per-inch maths. If there is any chance the code will one day be printed large, keep a big PNG — or better, the SVG — on file.

SVG: the professional default

SVG is the format to choose for anything designed or printed professionally: packaging, signage, business cards from a print shop, merchandise, vehicle graphics. Designers can open it in Illustrator, Inkscape or Figma, scale it freely, and change the module colour to your exact brand value — following the contrast rules in our design tips. SVG files are also tiny, and on the web they stay sharp on every screen density. If you are sending a code to anyone else to work with, send the SVG. It is the closest thing to a master file a QR code has.

EPS: the print-industry veteran

EPS is an older vector format that survives in traditional print workflows: some printers, sign shops and publishers still ask for it specifically. Functionally it does the same job as SVG — scalable shapes, sharp at any size — but with far less support in modern software and browsers. The practical rule: supply EPS when a printer requests it (most design tools can export an SVG design as EPS), and prefer SVG everywhere else. What matters is that the file reaching the press is vector, not which veteran format carries it.

A quick decision guide

  • Screen, documents, social, email: PNG, sized generously.
  • Any professional print or designer handoff: SVG.
  • Printer explicitly asks for it: EPS (converted from your vector).
  • Never: JPG for a QR code, or a screenshot of a code, or a small PNG stretched large — all three blur the edges scanners depend on.

Keeping a master file

However you publish the code, keep the SVG as your master and file it with the project it belongs to, named clearly — "menu-code-master.svg" beats "qr-final-v2". Months later, when the code needs to appear somewhere new at a new size, the master regenerates every version perfectly; the alternative, hunting for the largest surviving PNG and stretching it, is how fuzzy codes are born. If the code's content itself ever changes, generate a fresh master rather than editing the artwork, and replace every copy in circulation so old and new versions never mix in the wild.

Whichever format you choose, the code inside is identical — formats change the rendering, not the data — so the FAQ's short answer ("PNG for everyday, SVG for print") and this guide will always agree. Download both from the generator while you are there: the PNG for today's document, the SVG as the master for everything after.

QR Code Accessibility: Making Codes Everyone Can Use

A QR code assumes a user who can see the code, reach it, hold a phone steady and read the page it opens. Many people cannot do one of those things. Accessible design closes that gap — and usually makes the experience better for everyone else too.

Start with the honest principle

A QR code should be a shortcut, never the only route to whatever it offers. Every code you publish should have an alternative: the short web address printed beneath it, a staff member who can help, a paper version, a phone number. This single habit — visible throughout our restaurant guide and events guide — covers more accessibility failures than any technical fix, because it serves people whose barrier you did not anticipate as well as those you did.

Seeing and finding the code

People with low vision need codes they can locate and aim at. Print codes larger than the minimum — size is generosity here, and our sizes guide gives you headroom to give. Keep contrast maximal: black on white remains the most forgiving combination, ahead of brand colours. Place codes in consistent, predictable positions — always bottom-right of the poster, always on the table tent's front face — and say where they are in any accompanying text or audio ("there's a QR code at the bottom of this page"). A caption that states what the code does, in large clear type, helps everyone decide whether to scan.

For people who are blind, a printed code alone offers nothing; the alternative route is the accessibility. Where codes are central to a service, consider adding tactile or audio signposting — some venues pair codes with NFC tags or spoken instructions — but the printed short link and a human option remain the baseline.

Reaching and scanning the code

Placement is a mobility issue. A code at standing eye height is unreachable from a wheelchair and unusable for someone who cannot raise their arms or hold a phone steady at distance. Mount public codes within a comfortable reach band — roughly between waist and shoulder height for a seated person — and close enough that the phone need not zoom. Avoid codes on floors (trip hazard, impossible angle), behind glass (reflections), on curved surfaces, and anywhere scanning requires standing in a roadway or queue bottleneck. More placement detail lives in our best practices.

Generous size also helps people with tremor or limited fine motor control: a bigger code tolerates a less steady aim. High error correction adds further forgiveness when the camera cannot get a perfect read.

The page behind the code matters most

Accessibility does not end at the scan. The destination page is what the person actually came for, and it should meet ordinary web accessibility standards: readable text sizes without pinching, proper heading structure for screen readers, sufficient contrast, forms that work with assistive technology, and no information locked inside images alone. A menu code that opens an inaccessible scanned-image menu has moved the barrier, not removed it. If you commission one page for your codes, make it a genuinely accessible one.

Older phones and no phones

Finally, remember the device spectrum. Some users have phones old enough that scanning needs a separate app; some have no smartphone at all. Printed short links serve the first group; staff, paper and phone lines serve the second. Test your codes with the oldest phone you can find, in the real location — the same advice as our general testing guidance — and you will have done more for accessibility than any checklist alone. Then create the codes themselves with the generator, sized generously from the start.

QR Codes in Education: Practical Ideas for Teachers and Students

In a classroom, time is the scarcest resource, and typing a long web address from a whiteboard burns it thirty students at a time. QR codes hand that time back. Here are uses that survive contact with a real school day.

Instant access to resources

The foundational use: a code on a worksheet, textbook page or classroom poster that takes students straight to the video, simulation, article or document for that lesson. No typing, no "is that a zero or an O", no five-minute drift while the class finds the page. Print the code beside the task it belongs to, caption it ("Scan to watch the 4-minute recap"), and the resource and the work stay connected. For teachers, codes are free to make with a QR code generator and permanent once printed — the same worksheet set can serve for years, provided the destination page stays put, as our creation guide advises.

Support that differentiates quietly

Codes let one worksheet serve many levels. A code in the margin can open a hint video for students who are stuck, an audio version of the text for students who read better by listening, a worked example, or an extension challenge for early finishers. Because students choose when to scan, support arrives without singling anyone out — a genuinely inclusive pattern that connects with the thinking in our accessibility guide. Younger classes benefit too: a code on a reading-corner card that plays the story read aloud turns independent time into listening practice.

Displays, libraries and the physical school

Student work on walls gains a dimension with codes: the poster links to the recorded presentation, the art piece to the artist's statement, the science model to the experiment video. In the library, a code inside a book cover linking to reviews or the sequel's trailer makes recommendations self-service. Around the building, codes support scavenger-hunt lessons, nature-trail identification, equipment instructions in labs and workshops, and quick links to the school calendar or lunch menu — the same information-point pattern as any public signage, sized by the rules in our printing guide.

Administration without paper chains

Codes streamline the repetitive: a code on the classroom door or register desk linking to the absence or sign-in form, codes in planners linking to homework help and timetable pages, codes on letters home linking to permission forms and booking pages for parents' evening. Parents scanning a letter get the form open in seconds rather than losing the letter — a real improvement in return rates that school offices notice quickly.

Safety and good practice in schools

School codes carry school responsibilities. Link only to resources you have checked, on platforms your school approves, and remember that a printed code keeps pointing wherever it pointed — review destinations each year, because sites change. Teach students the habit from our safety guide: check the preview address before opening, and only scan codes from trusted sources — a lesson that protects them far beyond school. For student-created codes, the rule is the same as for any publishing: a teacher sees the destination before the code goes on a wall.

When devices are scarce

Not every classroom has a tablet per child, and codes still help. One shared device at a "scan station" can serve a whole group on rotation; a single code projected or printed large at the front lets a teacher demonstrate while students follow on paper; and for homework, codes on the printed sheet let families with one phone reach the help video without the school app login dance. Design for the devices your students actually have — including the option of a short printed web address beside every code — and the technology includes everyone instead of dividing the room.

Start small: one code on tomorrow's worksheet, linking to the one resource that matters. When the class is on task in twenty seconds instead of five minutes, you will not need convincing to use the rest of these ideas.

QR Codes for Real Estate: Signs, Flyers and Virtual Tours

Property marketing happens in the street: a passer-by pauses at a sign or a window card, interested for about ten seconds. A QR code converts that pause into full details, photos and a tour — before the moment passes.

The sign rider: your hardest-working code

The small sign beneath the main board — the rider — is where the code belongs, linking to that property's own page: full photo set, floor plan, room sizes, price, and the enquiry or booking button. A generic code to your agency homepage wastes the moment; the passer-by wants this house. Because each property needs its own code, and properties sell, the economics favour free static codes from a generator over per-code subscriptions — a point the static vs dynamic comparison makes in detail. Point each code at the property page on your own site, and when the home sells, update that page to "Sold — see similar homes" so the still-standing sign keeps generating enquiries instead of dead ends.

Size for the street, not the desk

Signs are scanned from the pavement, sometimes from across a front garden or a parked car — one to three metres is normal. That demands a big code: 10–15 cm at least, in a high-contrast panel on the rider, printed on weatherproof material with a matte finish. Our sizes and printing guide gives the distance maths; the short version is that a business-card-sized code on a yard sign is decoration, not a tool. Choose error correction level Q or H — outdoor codes get rained on, faded and splashed — and check signs on your rounds: a damaged rider is a silent enquiry leak.

Window cards and flyers

In the agency window, codes on property cards let browsers pull up full details and the virtual tour after hours, when the window does most of its selling. Flyers and newspaper adverts use smaller codes — 2.5–4 cm — scanned in the hand, linking to the same property page. One property, one destination, several code sizes: generate each at the right size rather than stretching one file, and use the formats in our file formats guide — SVG for the sign writer, PNG for the flyer designer.

Virtual tours and viewings

The destination that converts best is increasingly the virtual tour: a walkthrough video or 360° tour that lets a passer-by step inside immediately. Pair it with the practical next steps on the same page — book a viewing, download the particulars, see the energy rating, calculate the commute. Open-house days add their own codes: a check-in code at the door for visitor registration, and a feedback form code by the exit, replacing clipboard forms nobody completes.

Measuring what the street does

Lettings, auctions and commercial property

The same patterns stretch beyond sales. Letting agents put codes on to-let boards linking to viewing slots and application forms, cutting the phone tag that delays rentals. Auction houses add codes to lot boards and catalogue entries so bidders can pull up legal packs and condition reports on the spot. Commercial agents use larger boards with codes linking to floor areas, lease terms and agent contacts — information a passing business owner actually wants before calling. In each case the principle is identical: the board earns attention, the code delivers depth, and the page behind it does the persuading.

Property is where scan data earns money: knowing that one sign generated forty tour views while another generated two changes where you advertise. Give each property (or each board location) its own tagged link and read the results as our tracking guide describes. And keep the basics honest — caption every code ("Scan for photos, floor plan and tour"), keep details current, and remove codes when boards come down. A street presence that always leads somewhere accurate is an agency's reputation, printed.

Common QR Code Mistakes and How to Avoid Them

Almost every failed QR code fails for one of a handful of ordinary reasons — none of them mysterious, all of them preventable. Work through this list before your next print run and you will avoid nearly every dead code in the wild.

1. Printing too small

The champion mistake. A code squeezed into a leftover corner of a design, scanned from further away than its size allows, simply never resolves. The fix is planning: decide the scanning distance first, then size the code for it using the ratios in our sizes guide — 2 cm minimum in the hand, growing with distance. If the layout has no room for a working code, the layout needs changing, not the physics.

2. Weak contrast and creative colours

Pale gold on white, brand pastels, codes reversed out of dark backgrounds: all look refined and scan terribly, because cameras read brightness difference, not taste. Keep modules clearly darker than the background, be suspicious of any pairing your eye finds "subtle", and heed the contrast warning in the generator. Our design tips show how much branding freedom survives this rule — plenty, if you spend it around the code rather than inside it.

3. Cropping or crowding the quiet zone

The blank border around a code is functional, not wasted space. Designs that trim it, run text into it, or butt the code against a page edge produce codes that scanners cannot locate. Always export with the quiet zone on, and keep a clear margin beyond it in the layout. This mistake is especially common on business cards, where space pressure is worst.

4. Encoding too much

Long URLs with tracking strings, full contact cards, paragraphs of text: every extra character adds modules, shrinks each one, and narrows the margin for print size and damage. Shorten before you generate — use the shortest honest link, trim parameters, cut the vCard to essentials. Simpler codes scan faster, smaller and dirtier. If you genuinely need tracking parameters, keep them short, as the tracking guide advises.

5. Linking somewhere broken, slow or hostile

The code scans perfectly — and opens a 404, a desktop-only page, a huge PDF, or a site that demands an app install. The scan succeeded and the campaign still failed. Point codes at pages you control, keep them alive as long as the print lives, and make them fast and phone-first. The static vs dynamic article explains how owning the destination page prevents most of this category.

6. Bad surfaces and placements

Glossy glare, curved bottles, folds, deep shadow, codes behind window glass at noon, codes at ankle height or above head height: the environment defeats more codes than the printer does. Choose flat, matte, well-lit spots at a natural scanning height — the placement rules in best practices and the accessibility guide cover the details.

7. No caption, no context

A bare code asks strangers to scan a mystery. People rightly hesitate — unexplained codes are exactly what safety advice tells them to avoid — and scan rates suffer even when the code is technically perfect. One short line fixes it: what the code does and what the scanner gets. "Scan for the menu", "Scan to save my contact", "Scan for the house tour". It takes a line of space and converts suspicion into curiosity, which is why it appears in every use-case guide on this site.

8. Never testing the real thing

The meta-mistake behind all the others: approving a code from its screen preview. Screens are backlit, flat and perfect; print is none of those. Print one, place it, scan it with several phones including an old one, in the real light, at the real distance — then print the run. Every guide on this site ends with this advice because it is the step that catches every other mistake on this list while it is still cheap to fix. Generate your code with the free generator, run the test, and your codes will be the ones that simply work.
